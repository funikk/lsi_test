# load_tile ブロック仕様書

インターフェースとレジスタの定義は [spec_module_interfaces.md](../spec_module_interfaces.md) の第3章を正とする。本書では内部構成と動作の補足を記す。

## 1. 構成

| サブモジュール | クロック | 役割 |
|:--|:--|:--|
| `tile_ctrl` | `clk`（ゲートなし） | 境界FF、タイルIDのマッチング、4プロファイルのレジスタ、シードの展開、ソフトリセットとシード読み込みのパルス生成 |
| `tile_pattern_gen` | `clk` | 負荷のON/OFF（`load_on`）をサイクル単位で生成 |
| `vdrv_icg` | — | コアのクロックゲーティング |
| `tile_core_std` / `tile_core_lowact` / `tile_core_sram` | `gclk`（ゲートあり） | 負荷本体（`TILE_TYPE` で選択） |
| 出力FF | `clk` | `sig_out` の境界FF |

## 2. クロックゲーティング

ICGのイネーブルは次のとおり。

```
icg_en = ~GATE_MODE | load_on | sig_clear | seed_load | core_srst
```

- `GATE_MODE`=0：クロックは常に動く。負荷のOFFは、データを保持すること（`en`=0）で実現する。
- `GATE_MODE`=1：負荷がOFFの間はクロックを止める。制御パルス（クリア、シード読み込み、ソフトリセット）がある間だけ一時的にクロックを通す。
- リセット中は `GATE_MODE`=0 なので、AESコアの同期リセットにも必ずクロックが届く。

## 3. コアの種類

### 3.1 標準タイル（`tile_core_std`）
- 128bit LFSR（32bit LFSR×4。1サイクルで32ステップ進む）。
- データレジスタ `d`：ビットiは `(i % 16) < ACT_LEVEL` のときだけLFSRの値に更新し、それ以外は保持する。
- AES-128：ΣΔ方式のスロットルで、平均すると全サイクルの `ACT_LEVEL/16` の割合で起動する（`ACT_LEVEL`=16 なら、終わるたびにすぐ再起動）。平文＝`d`、鍵＝`d` の上位と下位64bitを入れ替えたもの。
- MACアレイ（`MAC_ROWS`×`MAC_COLS`）：入力は `d` のビットを固定の並べ方で割り当てる。
- シグネチャ：AES出力、MAC出力、AES完了フラグを32bitに畳み込み、`en` のサイクルにMISRへ取り込む。

### 3.2 低活性タイル（`tile_core_lowact`）
- `LOWACT_FFS` 段のシフトレジスタ。入力は「LFSRのビット AND（乱数4bit < `ACT_LEVEL`）」。`ACT_LEVEL`=0ならデータは変化せず、クロック網の電流だけになる。
- 標準の `LOWACT_FFS`=4096 で約5.5千セル（Yosysの汎用セル数）。

### 3.3 SRAMタイル（`tile_core_sram`）
- `SRAM_BANKS` 個の `vdrv_sram_wrap`（深さ `2^SRAM_AW` ×32bit）で、「アドレスNに書く → アドレスNを読む → N+1へ」を繰り返す。アクセスの頻度はΣΔスロットルで制御する。
- 読み出しデータはMISRに取り込む（書き込み済みのアドレスしか読まないので、Xが混入しない）。
- ローカル検証では `SRAM_AW`=6、商用では `SRAM_AW`=10（マクロに差し替え）を想定する。

## 4. SEED_LOADの動作

`TILE_CTRL[1]`（SEED_LOAD）を書くと、次の順で動く。
1. `core_srst` を1サイクル出す。データパスの全状態（LFSR、`d`、AES、MAC、MISR）を初期化する。
2. 次のサイクルで `seed_load` を出し、LFSRにシードを読み込む。

これにより、同じ設定のタイルは、それまでの履歴に関係なく同じシグネチャになる（対称性のチェックに使う）。リセットを解除した直後にも、既定のシード `0x12345678` を自動で読み込む。

## 5. 規模（Yosysの汎用セル数）

| 種類 | セル数 |
|:--|--:|
| 標準タイル（MAC 4×4） | 約21,000 |
| 低活性タイル（4096 FF） | 約5,500 |
