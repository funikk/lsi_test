# メモリモジュール仕様書 (`imem` / `dmem`)

## 1. 概要

本システムでは、CPUの命令フェッチ用 ROM/SRAM （`imem`）と、CPUおよび DMA エンジンが共有するデータ SRAM（`dmem`）の 2 つの独立メモリユニットを導入しています。

---

## 2. 命令メモリ仕様 (`imem`)

- **役割**: CPUからの命令フェッチ要求に応答し、32-bit RISC-V 命令（`firmware.hex`）を給餌。
- **構成**: シングルポート Read-Only メモリ。
- **メモリサイズ**: パラメータ `MEM_SIZE_WORDS` (デフォルト: 2048 ワード = 8KB)。合成時はロジック展開防止のため 128 ワード (512B) にパラメータ調整。
- **初期化**: `$readmemh("firmware.hex", mem);` によりシミュレーションおよび合成時に初期ロード。

### インタフェース信号
| 信号名 | 方向 | ビット幅 | 説明 |
| :--- | :--- | :--- | :--- |
| `clk` | Input | 1 | クロック |
| `rst_n` | Input | 1 | リセット |
| `valid_i` | Input | 1 | CPU 命令フェッチ要求 (`mem_valid_instr`) |
| `ready_o` | Output | 1 | メモリアクノリッジ応答 (`mem_ready_instr`) |
| `addr_i` | Input | 32 | 命令フェッチアドレス |
| `rdata_o` | Output | 32 | 32-bit 命令データ |

---

## 3. 共有データ SRAM 仕様 (`dmem`)

- **役割**: CPU のデータ領域および DMA 暗号化バッファとして機能するシングルポート SRAM。
- **アクセス調停**: CPU データバスと DMA エンジンからのアクセス要求を受信し、DMA 転送実行中は DMA に最優先アクセス権を割り当てます。
- **バイトアライメント**: 4 ビットのバイトストローブ `wstrb_i` により、1バイト (8-bit)、半ワード (16-bit)、フルワード (32-bit) の書き込みに対応。

### インタフェース信号
| 信号名 | 方向 | ビット幅 | 説明 |
| :--- | :--- | :--- | :--- |
| `clk` | Input | 1 | クロック |
| `rst_n` | Input | 1 | リセット |
| `valid_i` | Input | 1 | アクセス要求 |
| `ready_o` | Output | 1 | アクセス完了応答 |
| `addr_i` | Input | 32 | データアドレス |
| `wdata_i` | Input | 32 | ライトデータ |
| `wstrb_i` | Input | 4 | バイト書き込みストローブ (例: `4'b0001`: バイト0のみライト) |
| `rdata_o` | Output | 32 | リードデータ |
