# ロジック設計仕様書: crc_load_core

## 1. モジュール概要

`crc_load_core` は、電源電圧降下 (IR-Drop) およびエレクトロマイグレーション (EM) 耐性評価のための高負荷スイッチング・ストレステストベンチ向け負荷生成コアである。

128ビットの入力データに対し、4並列の32ビット巡回冗長検査 (CRC) / ガロア体多項式除算チャネル (`crc_channel`)、動的多項式マスク・係数展開ロジック、およびチャネル間の $GF(2^8)$ リード・ソロモン (Reed-Solomon: RS) シンドロームミキサーを組み合わせて、高密度・高頻度の論理トグルを発生させる。

### 設計特徴
- **高密度トグル誘発**: 48段の多項式除算段および $GF(2^8)$ 乗算器により、毎サイクル多数の論理ゲートが反転。
- **動的タップ構成**: 入力設定 (`cfg_in`) を動的多項式マスク (`poly_mask | 32'h04C11DB7`) として適用し、論理合成ツールによる論理畳み込み (Constant Folding) を完全に排除。
- **高拡散ミキサー**: 4チャネル間のバイトデータをリード・ソロモン符号のシンドローム生成 Vandermonde 行列に基づいて拡散・交差混合。
- **決定論的タイミング**: 1回の演算は固定10サイクル (`ITER_CYCLES`) で完了し、パイプラインおよびバックトゥバック連続実行に対応。

## 2. パラメータ仕様

| パラメータ名 | デフォルト値 | 説明 |
| :--- | :--- | :--- |
| `CHANNELS` | `4` | 並列CRC演算チャネル数 (4チャネル × 32ビット = 128ビット) |
| `UNROLL_STEPS` | `48` | 各チャネル内の多項式除算アンロール段数 (セル規模調整パラメータ) |
| `ITER_CYCLES` | `10` | 1ブロックあたりの反復演算実行サイクル数 |

---

## 3. 入出力ポート定義

| ポート名 | 方向 | ビット幅 | 説明 |
| :--- | :---: | :---: | :--- |
| `clk` | Input | 1 | システムクロック (立上りエッジ同期) |
| `rst_n` | Input | 1 | 非同期アクティブ・ロー・リセット |
| `start` | Input | 1 | 演算開始トリガ信号 (1サイクルパルス) |
| `data_in` | Input | 128 | 演算対象入力データ |
| `cfg_in` | Input | 128 | 動的多項式マスクおよび係数設定ベクトル |
| `data_out` | Output | 128 | 演算結果出力データ (演算完了時にラッチ保持) |
| `ready` | Output | 1 | コア準備完了 / アイドル状態表示信号 (1: 待機中/完了, 0: 演算実行中) |

## 4. ハンドシェイクおよびステートマシン動作仕様

### 4.1 ステート定義
- `STATE_IDLE` (`1'b0`): 待機状態。`ready` は `1'b1` を出力。
- `STATE_RUN` (`1'b1`): 演算実行状態。`ready` は `1'b0` を出力し、`ITER_CYCLES` (10) サイクル間継続。

### 4.2 タイミング動作シーケンス
1. **リセット動作 (`!rst_n`)**:
   - `state` は `STATE_IDLE` に初期化される。
   - `ready` は `1'b1` に初期化される。
   - `data_out` は `128'h0` にクリアされる。
2. **演算開始 (`start == 1'b1` かつ `ready == 1'b1`)**:
   - クロック立上りエッジで `data_in` および `cfg_in` を内部レジスタ (`state_reg`, `cfg_reg`) にラッチ。
   - `ready` を `1'b0` にネゲートし、`state` は `STATE_RUN` に遷移。
   - 内部イテレーションカウンタ `iter_cnt` を `0` に初期化。
3. **演算実行サイクル (`STATE_RUN`)**:
   - 各サイクル、4並列の `crc_channel` で32ビット多項式除算を実施。
   - チャネル出力はクロスチャネル $GF(2^8)$ リード・ソロモン・シンドロームミキサーに入力され、128ビット全体に拡散。
   - `cfg_reg` はサイクルごとにビット巡回および多項式タップ加算により動的更新され、毎サイクル異なる係数で演算を実行。
   - `iter_cnt` が毎サイクルインクリメントされる。
4. **演算完了サイクル (`iter_cnt == ITER_CYCLES - 1`)**:
   - 最終演算結果を `data_out` レジスタにラッチ。
   - `ready` を `1'b1` にアサート。
   - `state` は `STATE_IDLE` へ復帰。
5. **バックトゥバック連続実行**:
   - `ready == 1'b1` がアサートされたサイクルにおいて、直ちに次ブロックの `start == 1'b1` を入力可能。待機バブルサイクルなしで連続実行が可能。

## 5. データパス詳細構成

### 5.1 CRCチャネルモジュール (`blocks/crc_load_core/rtl/crc_channel.v`)
- 各チャネルは32ビットのデータスライスを処理。
- 有効多項式マスク:
  $$\text{poly\_mask} = \text{poly\_in} \mid 32\text{'h04C11DB7}$$
  IEEE 802.3 CRC-32 多項式をベースに `poly_in` の動的ビットを論理和合成することで、ゼロ縮退を防ぎつつ全ビットの動的変更を可能にする。
- アンロール除算ループ (48段):
  各段 $s \in [0, 47]$ において、フィードバックビット $\text{fb} = \text{st}[31] \oplus \text{coeff\_in}[s \bmod 32]$ を算出し、シフトおよび多項式加算を実行。

### 5.2 クロスチャネル $GF(2^8)$ リード・ソロモン・シンドロームミキサー
- 4つのチャネル出力 $ch\_dout[0..3]$ の各バイト位置 $b \in [0, 3]$ から4バイト $(b_0, b_1, b_2, b_3)$ を抽出。
- ガロア体 $GF(2^8)$ ($p(x) = x^8 + x^4 + x^3 + x^2 + 1$, `8'h1D`) 上の原始元 $\alpha = 2$ に基づく Vandermonde 型シンドローム評価式を適用:
  $$s_0 = b_0 \oplus b_1 \oplus b_2 \oplus b_3$$
  $$s_1 = b_0 \oplus (\alpha \cdot b_1) \oplus (\alpha^2 \cdot b_2) \oplus (\alpha^3 \cdot b_3)$$
  $$s_2 = b_0 \oplus (\alpha^2 \cdot b_1) \oplus (\alpha \cdot b_2) \oplus (\alpha^3 \cdot b_3)$$
  $$s_3 = b_0 \oplus (\alpha^3 \cdot b_1) \oplus (\alpha^2 \cdot b_2) \oplus (\alpha \cdot b_3)$$
- これにより、1チャネルの微小なビット変化が次サイクルの全4チャネルへ瞬時に波及拡散する。
